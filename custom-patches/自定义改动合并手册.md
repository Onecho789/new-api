> ### ⚠️ #5 #6 必读：为什么用具名常量而不是硬编码 `false`
>
> 早期版本写的是 `const isMapped = false` 和 `{false && ...}`。这两种写法**过不了检查**：
>
> - `false &&` 短路会让 TypeScript 丢失 `other` 的 null 收窄 → `bun run typecheck` 报两处 `TS18047: 'other' is possibly 'null'`
> - `{false && ...}` 还会触发 ESLint `no-constant-binary-expression`
>
> 解决办法就是现在这个写法：具名常量 + **显式标注 `: boolean`**（标注是关键，否则 TS 把类型收窄成字面量 `false`，问题依旧），并把上游原判断表达式保留在与运算右侧。
>
> 重做这两处时，**不要**退回硬编码 `false`。

#### #7 `common/model_mask.go`（响应体与错误文本共享脱敏）

放在 `common` 包（`service` 和 `relay/helper` 都能 import，无循环依赖）。

导出一个函数：

```go
func MaskUpstreamModelInData(c *gin.Context, data []byte) []byte
```

内部逻辑：从 context 读 `original_model`（请求模型）和 `model_mapping`（映射表），沿映射链收集所有真实上游模型名，对响应数据做**加引号精确替换** `"上游名"` → `"请求名"`。

三个关键设计点：

- **加引号替换**：`"claude-sonnet-4-6"` → `"claude-sonnet"`。加引号避免子串误伤（`gpt-4` 不会误伤 `gpt-4o`），且对 OpenAI / Claude / Gemini / SSE 各种 JSON 格式通用，无需按渠道分别解析。
- **快速路径**：无 `model_mapping` 或映射后与请求模型一致时，零开销原样返回。
- **context 缓存**：替换对缓存进 context（key `custom_model_mask_pairs`）；请求模型、渠道映射或真实上游模型改变时重建，覆盖切换渠道重试。
- **模型修饰符**：`ModelMappedHelper` 和 `ApplyReasoningModelSuffix` 通过 `SetUpstreamModelForMasking` 注册最终上游模型，支持基础模型回退和 `@effort` 等新语法；不在脱敏层重复实现修饰符解析。
- **JSON 编码**：替换值用项目 JSON 包序列化，正确处理模型名中的引号与转义。

**恢复**：删除此文件 + 移除 #8 #9 的 5 处调用。

**完整源码**：工作区 `common/model_mask.go`；归档见最新备份 `worktree-final.zip`。

**关键设计点**（改动时别踩）：

- **鉴权走 API Key，不走控制台会话**。`/v1/*` 端点认的是 `Authorization: Bearer sk-xxx`，所以 `api.ts` 里的 `generateImages` / `editImages` 用裸 `fetch` 而**不是**带会话拦截器的 `api` 实例；只有拉模型列表的 `/api/user/models` 用 `api`。
- **Key 存 localStorage 是明文**。默认**不存**，由用户显式勾选「记住」。这一点在 `storage.ts` 注释和界面文案里都写明了，别静默改成默认开启。
- **页面外壳必须用 `SectionPageLayout`**。`AuthenticatedLayout` → `SidebarInset` → `Main` 全是 `overflow-hidden` 的固定高度容器，直接用裸 `<Main>` 会导致内容被裁剪且不能滚动。路由文件里也**不要**再包一层 `Main`。
- **响应式用容器查询前缀**。`SidebarInset` 上有 `@container/content`，所以是 `@4xl/content:grid-cols-[20rem_minmax(0,1fr)]`，不是 `lg:`。
- **下载必须走 blob**。上游只回 `b64_json`，`src` 是数 MB 的 data URL，Chrome 会拦截顶层跳转到 data URL，`<a href={dataURL} download>` 静默失败。所以 `download-utils.ts` 走 `fetch(src) → blob → createObjectURL → click → revokeObjectURL`（同 `ai-elements/code-block.tsx` 的做法）。
- **objectUrl 必须配对释放**。`use-image-uploads.ts` 用 ref 保证卸载时能读到最新列表并 `revokeObjectURL`。
- **结果按模式隔离**。`images` 是一个数组，靠 `image.mode` 过滤，避免文生图页面里混进图生图的结果卡。另一模式有结果时给一行提示。

#### 蒙版语义（实测结论）

## 四、设计原理

### 为什么响应体脱敏选「统一出口拦截」

泄露点分散在几十个渠道适配器的流式 + 非流式路径中，分三类：

- **类型A**：显式 `.Model = info.UpstreamModelName`（cloudflare / coze / cohere / aws / gemini / ollama…）
- **类型B**：透传上游 `xxxResponse.Model`（convert.go / relay-claude.go / xai / ollama…）
- **类型C**：`IOCopyBytesGracefully` / `StringData` / `ClaudeChunkData` 直接透传上游原始 body/chunk（OpenAI/Claude/Gemini 默认路径，**最普遍**）

但无论哪一类、哪个渠道，响应最终都汇聚到极少数几个**统一发送出口**。在出口做一次字节替换，就能覆盖全部泄露点：

- **完整**：一处堵漏覆盖所有渠道/格式，包括未来新增的适配器
- **抗合并冲突**：只改 5 个底层发送函数，上游几乎不碰；逐点改要动 ~40 处，几乎每次合并都冲突
- **低风险**：不触碰各适配器的业务逻辑

### 错误日志与响应体共用映射解析

新版通过 `common.MaskUpstreamModelInText` 和 `common.MaskUpstreamModelInData` 共用映射与缓存。两个入口保留不同替换语义：自由文本按名称替换，JSON 按加引号的完整值替换。上游错误处理迁到 service 层后，HTTP 和 WebSocket 共用该出口，避免重复映射规则。

### 副作用与性能

- **副作用**：若助手回复正文里恰好出现被引号包裹的上游模型名，也会被替换成请求模型名。对「隐藏真实模型」这个目标而言可接受，且与报错日志脱敏策略一致。
- **性能**：仅当渠道配了 `model_mapping` 才替换；无映射时快速返回。有映射时每 chunk 一次小字符串替换 + context 缓存，开销可忽略。

## 十一、密钥分类管理（密钥分组）

### 功能边界与必须保留的行为

- 侧栏新增「密钥分组」入口 `/key-groups`，管理当前用户自己的单层分类：查看分类名称与密钥数量、新增、重命名、删除、查看该分类内的密钥。分类名去除首尾空白，长度为 1–64 个 Unicode 字符，同一用户下名称唯一，不同用户互相隔离。
- 「查看密钥」跳转到已有 `/keys?category_id=<分类ID>` 页面，复用原 API 密钥列表与新增、编辑、删除流程；新增默认选中当前筛选分类。密钥列表显示分类，并支持全部分类、未分组、指定分类筛选，以及与现有名称/密钥搜索和服务端分页组合使用。
